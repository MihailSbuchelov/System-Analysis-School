## 1. Основы (5–18 мин)

«Показываю простую диаграмму. [рисую на экране или показываю готовую]:

```
Клиент          OrderService         PaymentService        DB
  |                  |                      |               |
  |--- POST /orders -->|                      |               |
  |                  |--- charge(5000) ----->|               |
  |                  |                      |--- SELECT --->|
  |                  |                      |<-- ok --------|
  |                  |<-- {PAID, tx:99} ----|               |
  |                  |--- INSERT order ---->|               |
  |                  |                      |               |
  |<-- 201 {id:42} --|                      |               |
```

Разбираю элементы:

**Lifeline** — вертикальная пунктирная линия под каждым участником. Каждый участник (система, сервис, БД) — **отдельная lifeline**.

**Сообщения** — стрелки между lifelines:

| Вид | Как рисуется | Значение |
|---|---|---|
| `->>` (сплошная, стрелка) | `A ---> B: запрос` | **Синхронный** вызов: жду ответ |
| `-->>` (пунктирная, стрелка) | `A <-- B: ответ` | **Return**: ответ на синхронный вызов |
| `->>` без return | `A ---> Kafka: publish` | **Асинхронное**: положил, не жду |

**Вопрос: какая стрелка sync, а какая return? Почему return пунктирная?**»

[Ожидаю: «сплошная — sync, пунктирная — return. Return пунктирная, потому что это ответ, не новый запрос». Если не говорит — объясняю: «sync = "я пошёл и жду". Return = "вот что ты ждал". Это разные вещи, поэтому разные стрелки».]

**БД как участник.**

«Обрати внимание: **DB — отдельная lifeline**, не "внутри" OrderService. Показываю, где именно происходит SELECT и INSERT.

Вопрос: почему БД — отдельный участник, а не часть сервиса?»

[Ожидаю: «потому что это другая система, с собственным временем отклика, может упасть». Если не говорит —:]

«БД — отдельная система. Она может быть на другом сервере, может упасть, может быть медленной. На диаграмме мы показываем, **где именно** сервис читает/пишет в БД — это важно для отладки и для понимания, где может быть таймаут.»

**Self-message.**

«Иногда сервис вызывает метод сам в себе:

```
OrderService
  |
  |--- validate(items) -->  (self)
  |--- checkStock() -------> (self)
  |--- charge() ------------> PaymentService
```

Это не отдельная система, а **логика внутри одного сервиса**. Рисуем как стрелку от lifeline к самой себе.

**Активация** (activation box) — прямоугольник на lifeline. Показывает, что объект **в этот момент работает**. Если активация длинная — сервис долго занят.

## 2. Фреймы (18–35 мин)

«Фрейм — прямоугольник вокруг части диаграммы с надписью. Означает: "внутри — ветвление/повтор/условие".

### alt (if/else)

```
OrderService          PaymentService
  |                        |
  |--- charge(5000) ------>|
  |                        |
  alt [карта одобрена]
  |<-- {PAID} ------------|
  |--- 201 --> Client
  |
  else [карта отклонена]
  |<-- {DECLINED} --------|
  |--- 409 --> Client
  end
```

**На каждой ветке alt — условие.** Не просто "ветка 1 / ветка 2", а "[карта одобрена]" / "[карта отклонена]".

### opt (может быть)

```
OrderService
  |
  opt [есть промокод]
  |--- applyPromo("SAVE10") --> PromoService
  |<-- {discount: 500} ------|
  end
  |
  |--- INSERT order --> DB
```

"Если промокод есть — применяем. Если нет — пропускаем этот блок."

### loop (повтор)

```
OrderService          Kafka
  |                      |
  loop [retry до 3 раз]
  |--- publish --------->|
  |<-- ack --------------|
  end
```

"Публикуем. Если не пришли ack — повторяем до 3 раз."

### break (выход)

```
OrderService          PaymentService
  |                        |
  |--- charge(5000) ------>|
  |                        |
  break [timeout > 5 сек]
  |--- 503 --> Client
  end
```

"Если timeout — выходим из последовательности, возвращаем ошибку."

**Вопросы:**
- «Какой фрейм для "может быть промокод"?» → **opt**
- «Какой для "retry 3 раза"?» → **loop**
- «Какой для "если timeout — бросаем"?» → **break**
- «Какой для "карта одобрена / отклонена"?» → **alt**

## 3. Частые ошибки (35–45 мин)

«Теперь — что обычно делают не так. Прохожу по таблице:

| Ошибка | Как правильно |
|---|---|
| Все стрелки sync, нет return | Для каждого `->>` — либо `-->>` return, либо это async (без return) |
| Нет БД как участника | БД — отдельная lifeline, SELECT/INSERT явно |
| `alt` без условий | На каждой ветке: `[условие]` |
| Kafka выглядит как sync | Kafka: стрелка **без return** (async) |
| 10+ lifelines | Сгруппировать: "PaymentSystem" вместо 5 микросервисов |
| Нет порядка (всё в кучу) | Sequence = время. Сверху вниз — хронология |

**Вопрос: что не так с диаграммой, где `Client ->> Server: POST /orders` и сразу `Server ->> Client: 201`, но нет БД и нет проверки оплаты?**»

[Ожидаю: «нет БД (где пишется заказ?), нет платёжного сервиса (где проверяют оплату?), нет ветвления (что если оплата не прошла?)». Если не говорит — подсказываю по пунктам.]
