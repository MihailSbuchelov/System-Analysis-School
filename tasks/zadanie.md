# Задание. Интернет-магазин: модель данных, индексы, REST API

## Контекст

Небольшой интернет-магазин электроники. 500 товаров, 2000 пользователей, ~200 заказов в день.
Сейчас всё в Excel, продукт просит веб-приложение: пользователь просматривает каталог, кладёт в корзину, оформляет заказ, оплачивает.

Задача: **спроектировать модель данных и REST API** для двух сценариев.

---

## Дано: опорная таблица

Таблица `products` уже спроектирована и зафиксирована. Не менять.

```sql
CREATE TABLE products (
    id          INTEGER PRIMARY KEY,
    name        VARCHAR(200) NOT NULL,
    category    VARCHAR(50)  NOT NULL,      -- 'phones', 'laptops', 'accessories'
    price_cents INTEGER      NOT NULL,      -- цена в копейках
    stock       INTEGER      NOT NULL DEFAULT 0,
    created_at  TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);
```

---

## Что нужно спроектировать

### 1. Модель данных (не более 5 таблиц)

`products` уже есть. Спроектируй **остальные** таблицы (не более 4 новых), чтобы покрыть оба сценария.

Для каждой таблицы:
- название
- поля (название, тип, обязательность, ограничения)
- первичный ключ, внешние ключи
- ограничения (CHECK, UNIQUE)

Подсказки:
- Кто покупает? Какие данные о нём храним?
- Что такое заказ? Какие у него стадии?
- Заказ содержит товары. Как связать заказ и товар?
- Нужна ли история цен? (на этом этапе — нет)

### 2. Индексы

Для каждого частого запроса (из сценариев ниже) предложи индекс:
- какие колонки и в каком порядке
- почему именно такой порядок

### 3. REST API

Опиши эндпоинты для обоих сценариев:
- метод, путь
- запрос (body / query params)
- ответ (статус + тело)
- ошибки (какие 4xx могут быть)

### 4. SQL-запросы

Для ключевых шагов сценариев напиши SQL (SELECT / INSERT / UPDATE).

### 5. Описание целевых сценариев

Опиши **два** целевых сценария (по 5–7 строк на каждый):
- какие таблицы читает/пишет система на каждом шаге
- что происходит при ошибке (нехватка товара, двойной клик, чужой заказ)
- какой REST-эндпоинт обслуживает сценарий

Сценарии должны покрывать:
1. **Создание заказа** (синхронный, запись): пользователь оформляет заказ → проверка наличия → списание со склада → ответ
2. **Просмотр своих заказов** (синхронный, чтение): список заказов + детали заказа

Опиши **своими словами**, что происходит на каждом шаге. Не копировать из постановки.

---

## Ограничения

- Не более **5 таблиц** всего (включая `products`)
- Деньги — **integer в копейках**, не float
- Даты — **TIMESTAMPTZ** (ISO 8601)
- Статусы — **enum** (перечислить значения)
- Индексы — только под **частые** запросы, не «на всё подряд»

---

## Формат сдачи

1. **ERD** (рисунок: draw.io, бумага, Mermaid) — все таблицы, связи, PK/FK
2. **DDL** — `CREATE TABLE` для каждой новой таблицы
3. **Индексы** — таблица: запрос → индекс → почему
4. **REST API** — таблица: метод, путь, body, ответ, ошибки
5. **SQL** — 4–6 запросов для ключевых шагов
6. **Ответы на вопросы** из сценариев (по 2–3 строки на каждый)
