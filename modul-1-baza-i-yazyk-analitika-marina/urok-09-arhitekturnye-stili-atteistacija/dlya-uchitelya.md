## 4. Сценарий по шагам

### 4.1. Вступление (3 мин)
Объявить: это финальный урок модуля 1 — аттестация. Напомнить рубеж: модуль 1 закрывает базу; модуль 2 начинает процессную сторону анализа.

### 4.2. Архитектурные стили (17 мин)
Объяснить заданное понятие «стиль» — не рамки, а язык. Разобрать по слайдам:

- **Монолит.** Понятная метафора: «один锅炉 = всё в одном доме». Плюсы/минусы подчеркнуть: рядом — когда просто, и когда хаос.
- **Модульный монолит.** Важно не путать с «просто красивым кодом»: границы публичных интерфейсов — ключевое.
- **Микросервисы.** Метафора: «городская больница → несколько профильных центров». Важно: не «модно», а «оправдано при необходимости».
- **Событийный подход.** Напомнить Observer из урока 8, теперь в масштабе системы: очередь событий, подписчики не знают друг о друге.

Показать слайд «Как выбрать стиль». Спросить: «а для вашего учебного сервиса — какой?».

### 4.3. Правила аттестации (5 мин)
Разобрать задание: 20 минут письменно, затем защита 5–7 мин + вопросы. Сформулировать критерии (слайд «Критерии аттестации»).

### 4.4. Практика: подготовка к аттестации (20 мин)
Ученики собирают ответ: схема + роли + путь запроса + стиль + сущности. Учитель ходит, смотрит, отвечает на уточняющие вопросы, но не даёт готовых ответов.

**Подсказки, если ученик застрял:**
- «Какие у вас части? Начните с браузера».
- «Какой стиль ближе всего, если сервис небольшой?».
- «Что в вашей БД — товары, клиенты, заказы?»

### 4.5. Защита аттестации (23 мин)
Организовать выступления. Формат: ученик показывает схему, объясняет, отвечает на вопросы.

**Вопросы для защиты (см. раздел 7):**
- «Какой стиль и почему?»
- «Что, если вместо 10 пользователей будет 1000?»
- «Где здесь "логика", а где "данные"?»
- «Что было бы в интеграции с внешней платёжной системой?» (мост к модулю 3, интеграции).

Следить за темпом, не давать вопросам «расползтись».

### 4.6. Дополнительные вопросы и обсуждение (7 мин)
После защиты задать группе: «Что общего между монолитом и слоями из урока 8?». Подвести к выводу: слои — внутреннее устройство; монолит/микросервисы — масштабная архитектура. Слои существуют **внутри** каждого сервиса микросервисной архитектуры.

### 4.7. Итоги модуля 1 (5 мин)
Напомнить путь модуля: части приложения → HTTP → БД → ООП → SOLID → слои → стили. Сказать: «это ваша база; модуль 2 начнёт процессную сторону аналитика».

Разобрать формулировки ДЗ. Вопрос к заданию №2: принести 3 аргумента «за/против» — устно обсудим в начале следующего урока.

## 6. Типичные ошибки и как реагировать

| Ошибка | Реакция учителя |
|---|---|
| «Микросервисы всегда лучше» | Напомнить про complexity: для 3 человек лишняя распределённость |
| Путает монолит с «код в одном файле» | Уточнить: монолит может быть хорошо структурированным |
| «Мой стиль — не монолит, потому что я разделил на модули» | Уточнить: модульный монолит = границы **внутри** одного процесса |
| Забывает назначить сущности ключи | Напомнить: PK обязателен, FK для связей |
| Не может ответить «а что, если рост?» | Помочь подсказкой: кэширование, шардирование, выделение горячих частей |
| Стиль выбран, но «для галочки» | Задать уточнение: «что станет, если выберете другой?» |

## 7. Вопросы для защиты аттестации

Использовать 4–5 из списка:

1. «Какой архитектурный стиль вы выбрали и почему?»
2. «Покажите путь одного запроса по вашей схеме».
3. «Какие данные хранятся в вашей БД? Что связывает сущности?»
4. «Что произойдёт, если БД упадёт, а сервер жив?» (мост: слои + репозиторий из урока 8).
5. «Если мы добавим интеграцию с платёжным сервисом, где она будет на схеме?» (модуль 3: интеграции, HTTP/события).
6. «Чем ваша система отличается от "одного файла Excel"?» (клиент-сервер, сеть, безопасность — урок 1).
7. «Какая часть системы — логика, а какая — данные? Почему их разделяют?»

## 8. Домашнее задание — разбор и ответы

1. **Оформление по шаблону** — ученик пишет разбор по 5 пунктам задания (см. презентацию). Проверяется по чек-листу аттестации.
2. **Статья монолит vs микросервисы** — основные аргументы:
   - Монолит: просто, быстрый старт, транзакции, одна деплой-процедура.
   - Микросервисы: независимые релизы, горизонтальное масштабирование, гибкость технологий.
3. **Критичные транзакции:** для «магазина» — оформление заказа и списание; для «банка» — перевод между счетами (ACID из урока 5).
