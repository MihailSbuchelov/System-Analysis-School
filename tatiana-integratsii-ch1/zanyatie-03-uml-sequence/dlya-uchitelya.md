### 4.1. Вступление (5 мин)

### 4.2. Основы (13 мин)
Показать простую диаграмму (из §2 презентаци, mermaid). Разобрать:
- **Lifeline** — вертикальная пунктирная линия под каждым участником.
- **Sync** (`->>`) — сплошная стрелка, жду ответ.
- **Return** (`-->>`) — пунктирная стрелка, ответ.
- **Async** — стрелка без return (или пунктир + подписка на Kafka).
- **БД** — отдельная lifeline, не «внутри» сервиса.

Вопросы:
- «Какая стрелка sync, а какая return?»
- «Почему return пунктирная?» (ответ, не запрос)
- «Где БД?» (отдельная lifeline, SELECT/INSERT)

### 4.3. Фреймы (17 мин)
Показать `alt` (оплата: одобрена/отклонена) и `loop` (retry 3 раза).
Разобрать:
- `alt` — if/else, на каждой ветке **условие**.
- `opt` — «может быть» (промокод).
- `loop` — повтор (retry).
- `break` — выход (ошибка, abort).

Вопросы:
- «Какой фрейм для "может быть промокод"?» (opt)
- «Какой для "retry 3 раза"?» (loop)
- «А если "если timeout — бросаем"?» (break)

## 6. Типичные ошибки и как реагировать

| Ошибка | Реакция |
|---|---|
| «Sequence = flowchart» | Развести: sequence — время + участники, flowchart — логика одного процесса |
| Все стрелки sync, нет return | Для каждого `->>` — либо return `-->>`, либо async (без return) |
| Нет БД как участника | БД — отдельная lifeline, показываются SELECT/INSERT/UPDATE |
| `alt` без условий | На каждой ветке — условие: `[одобрена]`, `[отклонена]` |
| Kafka выглядит как sync | Async: стрелка без return, или пунктир + подписка |
| 10+ lifelines | Сгруппировать: «PaymentSystem» вместо 5 микросервисов |
| «Я не умею рисовать UML» | draw.io — перетаскивание фигур, не надо «рисовать от руки» |
| Рассказ: «я нарисовал» вместо «вот как работает» | Вернуть к формуле: участники → поток → ветвление → async → ошибки |

## 9. Ресурсы

- **draw.io** (app.diagrams.net) — бесплатно, UML-фигуры, экспорт PNG/SVG.
- **PlantUML** (plantuml.com) — текстовый формат, генерация. Пример:
  ```
  @startuml
  participant Client
  participant OrderService
  database DB
  Client -> OrderService: POST /orders
  OrderService -> DB: INSERT
  DB --> OrderService: ok
  OrderService --> Client: 201
  @enduml
  ```
- **Mermaid** (mermaid.live) — встроено в GitHub/Notion, синтаксис проще PlantUML.
- **Miro/Lucidchart** — если в компании есть.
- UML Sequence Spec: omitto.com (или любой UML-референс).

## 10. Заметки по проведению

- **Практика — ядро.** 25+ минут на рисование. Не торопить, пусть думает.
- Если нет доступа к draw.io/Mermaid — **бумага и ручка**. Главное — логика, не красота.
- **Якорь «БД — отдельная lifeline»** — если не рисует, повторить 3 раза.
- **Якорь «async = без return»** — Kafka, уведомления. Если рисует return от Kafka — поправить.
- Рассказ на собесе: **она проговаривает вслух**, я слушаю. Не «я проверю рисунок», а «расскажи, как работает».
- Формат: если «диалог» из ч.1/ч.2 сработал — продолжать. Если нет — «показываю → она резюмирует → рисуем вместе».
