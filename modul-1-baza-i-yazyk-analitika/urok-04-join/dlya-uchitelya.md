## 4. Сценарий по шагам
### 4.1. Вступление и проблема (3–5 мин)
Показать две таблицы: `users` и `orders`. Спросить: «Как получить имя покупателя и дату его заказа в одном запросе?» Ученик, скорее всего, предложит два запроса. Это тот случай, когда SQL не поможет без JOIN — нужны два обращения к БД. JOIN решает проблему: «один запрос — один ответ с данными из разных таблиц».

Важный акцент для будущего аналитика: аналитик формулирует требования к данным. Если данные в разных таблицах — аналитик должен знать, что для связи потребуется JOIN. Это влияет на проектирование БД и качество данных.
### 4.2. Связи и внешние ключи (7 мин)
Показать ER-диаграмму (слайд 4). Объяснить:
- **Внешний ключ (FK)** — колонка, которая ссылается на ID другой таблицы.
- `orders.user_id` → `users.id` («этот заказ сделал пользователь №1»).
- Связь «один-ко-многим»: один пользователь может сделать много заказов.

Задача на понимание: «Какой внешний ключ в `order_items`?»
Ответ: `order_id` (ссылается на `orders.id`) и `product_id` (ссылается на `products.id`).
### 4.3. INNER JOIN (8 мин)
Показать таблицы users и orders. Запрос:

```sql
SELECT users.name, orders.order_date
FROM users
INNER JOIN orders ON users.id = orders.user_id;
```

Результат:
| name | order_date |
|------|------------|
| Анна | 2025-03-01 |
| Анна | 2025-03-05 |
| Пётр | 2025-03-10 |

**Ключевой момент:** Мария (id=3) **отсутствует** — у неё нет заказов, и INNER JOIN её не покажет.

Метафора: «INNER JOIN — это пересечение двух списков: только те, кто есть в обоих».
### 4.4. LEFT JOIN (8 мин)
Тот же запрос, но с LEFT JOIN:

```sql
SELECT users.name, orders.order_date
FROM users
LEFT JOIN orders ON users.id = orders.user_id;
```

Результат:
| name | order_date |
|------|------------|
| Анна | 2025-03-01 |
| Анна | 2025-03-05 |
| Пётр | 2025-03-10 |
| Мария | NULL |

**Ключевой момент:** Мария теперь видна. `order_date = NULL` — это код «нет данных из правой таблицы».

Когда используется LEFT JOIN:
- «Покажи всех клиентов и их заказы» (включая тех, кто ничего не покупал)
- Поиск записей без связей (LEFT JOIN + WHERE ... IS NULL)
### 4.5. RIGHT JOIN (3 мин)
RIGHT JOIN — зеркальный LEFT. Возвращает **все строки из правой** + совпадения из левой.

В учебном примере результат совпадает с INNER JOIN, потому что все заказы связаны с пользователями. Но если бы в orders был `user_id = 99` (несуществующий), RIGHT JOIN показал бы и его.

Практический совет: RIGHT JOIN используется редко. Проще поменять таблицы местами и использовать LEFT JOIN.
### 4.6. SELF JOIN (7 мин)
Показать таблицу `staff`:

| id | name | manager_id |
|----|------|------------|
| 1 | Иван | NULL |
| 2 | Пётр | 1 |
| 3 | Анна | 1 |
| 4 | Мария | 2 |

Запрос:

```sql
SELECT e.name AS сотрудник, m.name AS руководитель
FROM staff e
LEFT JOIN staff m ON e.manager_id = m.id;
```

Результат:
| сотрудник | руководитель |
|-----------|-------------|
| Иван | NULL |
| Пётр | Иван |
| Анна | Иван |
| Мария | Пётр |

**Ключевой момент:** `e` и `m` — это **алиасы** (псевдонимы) одной и той же таблицы `staff`. Без алиасов SQL не понял бы, какую «копию» использовать.

Для аналитика: SELF JOIN часто встречается в organizational charts, threaded comments (комментарий → ответ), классификациях (категория → родительская категория).
### 4.7. ON vs WHERE (5 мин)
Объяснить разницу:
- **ON** — задаёт условие соединения (какие строки «склеивать»)
- **WHERE** — фильтрует результат **после** соединения

Показать на примере:
```sql
SELECT users.name, orders.order_date
FROM users
LEFT JOIN orders ON users.id = orders.user_id
WHERE orders.order_date IS NOT NULL;
```

LEFT JOIN + `WHERE order_date IS NOT NULL` = INNER JOIN.

Это важно для понимания: неверное размещение условия в JOIN-запросе может радикально изменить результат.
### 4.8. Практика 1 (18 мин)
Задания:
1. Список всех заказов с именами покупателей (LEFT JOIN)
2. Товары, которые никто не покупал (LEFT JOIN + NULL)
3. Список товаров в заказе №1 с названиями

**Ожидаемые ответы:**

1. ```sql
   SELECT users.name, orders.order_date, orders.id AS order_id
   FROM users
   LEFT JOIN orders ON users.id = orders.user_id;
   ```
   | name | order_date | order_id |
   |------|------------|----------|
   | Анна | 2025-03-01 | 1 |
   | Анна | 2025-03-05 | 2 |
   | Пётр | 2025-03-10 | 3 |
   | Мария | NULL | NULL |

2. ```sql
   SELECT products.name
   FROM products
   LEFT JOIN order_items ON products.id = order_items.product_id
   WHERE order_items.id IS NULL;
   ```
   Результат — пустая таблица: все товары хотя бы раз заказывали. Если добавить товар «Ручка» (id=5), он появится в результате.

3. ```sql
   SELECT products.name, order_items.qty, products.price
   FROM order_items
   JOIN products ON order_items.product_id = products.id
   WHERE order_items.order_id = 1;
   ```
   | name | qty | price |
   |------|-----|-------|
   | Ноутбук | 1 | 89000 |
   | Наушники | 2 | 3500 |

## 6. Типичные ошибки и как реагировать

| Ошибка | Реакция учителя |
|---|---|
| «JOIN = WHERE» | Показать разницу: JOIN связывает таблицы, WHERE фильтрует результат |
| «LEFT и INNER — одно и то же» | Показать результат с Марийей: в LEFT она есть, в INNER — нет |
| Забывает алиасы для SELF JOIN | Напомнить: без алиасов SQL не понимает, какую «копию» таблицы использовать |
| Ставит условие в WHERE вместо ON | Показать: LEFT JOIN + WHERE IS NOT NULL = INNER JOIN |
| Путает LEFT и RIGHT | Напомнить: LEFT = приоритет левой таблицы, RIGHT = приоритет правой |

## 8. Домашнее задание — разбор и ответы

1. **Покупатели + количество заказов:**
```sql
SELECT users.name, COUNT(orders.id) AS total_orders
FROM users
LEFT JOIN orders ON users.id = orders.user_id
GROUP BY users.id, users.name;
```
| name | total_orders |
|------|-------------|
| Анна | 2 |
| Пётр | 1 |
| Мария | 0 |

2. **Товары, заказанные больше 1 раза:**
```sql
SELECT products.name, SUM(order_items.qty) AS total_qty
FROM products
JOIN order_items ON products.id = order_items.product_id
GROUP BY products.id, products.name
HAVING SUM(order_items.qty) > 1;
```
| name | total_qty |
|------|----------|
| Наушники | 2 |
| Чехол | 3 |

3. **LEFT JOIN + WHERE по правой таблице:**
LEFT JOIN возвращает все строки из левой + совпадения. Если мы добавляем `WHERE order_date IS NOT NULL`, отсеиваем все строки, где нет совпадения из правой таблицы. В итоге остаются только совпадения — это эквивалент INNER JOIN.

4. **Примеры SELF JOIN:**
- Комментарий → ответ на комментарий (threaded comments)
- Товар → родительская категория (иерархия категорий)
